# Берёзы вдали: карточки, импосторы и лесная полоса — предложение для интеграции

Для Codex (ride3d) и Дарьи. Здесь только ассеты и план. Код приложения не трогали.
Источник: берёза TurboSquid 2561468 (LOD0 из `out/birch_source.blend`). Лицензия: TurboSquid Standard / royalty-free, точное название подтвердит Дарья.

## 1. Схема дальностей

Расстояние меряется от камеры до основания ствола, по горизонтали.

| | `q=low` | `q=med` (согласованный план) | `q=high` |
|---|---|---|---|
| `birch_lod0.glb` (3652 tris) | 0–12 м | 0–20 м | 0–30 м |
| `birch_lod1.glb` (1349 tris) | 12–25 м | 20–40 м | 30–60 м |
| Кросс-карточки `birch_card_cross.glb` (4 tris) | 25–180 м, за 120 м прореживать каждое второе дерево | 40–300 м | 60–150 м: `birch_card_3plane.glb` (6 tris); 150–400 м: cross |
| Лесная полоса `forest_band_color` | ~190 м | ~310 м | ~410 м |
| Туман `FogExp2.density` (≈85 % тумана на полосе) | 0.0069 | 0.0046 | 0.0034 |
| Зона кросс-фейда LOD1↔карточки | 3 м | 4 м | 6 м |
| Подлесок (только у кромки леса) | ≤ 60 м, ≤ 80 шт. | ≤ 100 м, ≤ 200 шт. | ≤ 150 м, ≤ 400 шт. |
| MSAA + `alphaToCoverage` | нет, только `alphaTest 0.5` | нет (включать, если fps > 50) | MSAA 4x + `alphaToCoverage` |
| Освещение карточек по normal-атласу | нет (wrap-Lambert по «сферической» нормали) | да | да |

Если в сцене есть свой `forestFog.ts`, плотность тумана задаётся им. Важно одно: на полосе туман должен закрывать ≈ 80–90 %.

## 2. Ассеты и соглашения

- **Атлас** `birch_cards_color` 2048² RGBA, альфа в A, и `birch_cards_normal` (тот же UV-лэйаут, но отгружается в 1024²).
  - 4 ряда — варианты деревьев: v0 оригинал, v1 зеркальный, v2 стройный/редкий, v3 зеркальный/широкий/«позднее лето».
  - 8 колонок — азимуты 0…315° с шагом 45°. Ячейка 256×448 px покрывает 3.31×5.79 м.
  - Нижняя полоса 256 px: 4 ячейки подлеска по 512×256 (2.4×1.2 м).
  - UV-прямоугольники, пивоты и размеры каждой ячейки лежат в `birch_cards.json`. UV там в конвенции glTF/three: начало в левом верхнем углу, `flipY=false`.
- **Освещение запечено нейтрально**: неосвещённый альбедо × мягкий AO (0.62…1). Направленного света и теней нет, свет сцены накладывается в шейдере.
- **Normal-атлас** содержит нормаль в пространстве «карточка/вид»: x вправо (u), y вверх, z к зрителю, кодировка `n*0.5+0.5`. Это обычная OpenGL tangent-space карта для вертикального квада. У листвы нормаль — 50 % нормали листа + 50 % «сферической» нормали кроны, чтобы крона освещалась объёмно.
- **Меши**: начало координат у основания ствола, Y вверх.
  - **Единица = высота дерева v0**, так что `instance scale = желаемая высота дерева в метрах`, обычно 14–20. Варианты v2 и v3 получатся на +12 % и −5 % выше или ниже, это естественный разброс.
  - Квад 0.670×1.172 ед., пивот на 2.2 % выше нижнего края.
  - `understory_card_cross.glb`: ширина 1.0 = 2.4 м, `scale` = ширина куста в метрах / 2.4 (обычно 0.8–1.4).
- **Лесная полоса** `forest_band_color` 2048×256: плитка 64×8 м, бесшовная по горизонтали (`wrapS = RepeatWrapping`). Нижняя часть непрозрачная («лесная чаща»), сверху альфа по силуэту крон. Её можно натянуть на кольцо или цилиндр радиусом R вокруг камеры, двигать вместе с камерой по XZ и масштабировать ×3–3.5, чтобы деревья были 15–20 м.
- **Mip-уровни цветовых KTX2 сохраняют покрытие альфы** (`coverage_mips.py`), поэтому кроны вдали не «тают». С обычными mip к 4-му уровню (≈ 30 px) терялось 24 % листвы.

## 3. InstancedMesh

- По одному `InstancedMesh` на тип (cross, 3plane, understory, а billboard — по желанию) и на чанк ландшафта, как у текущих деревьев. Чанки рисовать от ближнего к дальнему, чтобы сработал early-Z.
- Атрибуты на экземпляр, через `InstancedBufferAttribute`:
  - `aCell` (vec2): `row` 0..3 — случайный вариант; `colShift` 0..7 — случайный поворот набора азимутов;
  - `aTint` (vec3): сдвиг оттенка ±0.03, яркость 0.85–1.10, насыщенность 0.9–1.1;
  - `aFade` (float), если нужен кросс-фейд по экземпляру.
- **UV в вершинном шейдере** (ячейка ровно 1/8 по u, 448/2048 по v):
  ```glsl
  float col = floor(uv.x * 8.0);
  uv.x += (mod(col + aCell.y, 8.0) - col) / 8.0;   // поворот азимутов cross/3plane
  uv.y += aCell.x * (448.0 / 2048.0);              // вариант (ряд)
  ```
- **Billboard-импостор** (необязателен, 2 tris): цилиндрический поворот к камере в вершинном шейдере. Колонка = `round(atan(dir.x, dir.z) / (PI/4))` по модулю 8, где `dir` — вектор от дерева к камере в локальных осях экземпляра (с учётом его yaw). Азимут 0 = вид с +Z (glTF), против часовой стрелки сверху. Если щелчок при смене колонки заметен, смешивать две соседние колонки.

## 4. Шейдер карточек

`MeshLambertMaterial` + `onBeforeCompile`, или свой `ShaderMaterial` с чанками three. Без спекуляра.

1. **Цвет**: `texture(map, uv)`. `if (a < 0.5) discard;` — это `alphaTest`. При MSAA вместо этого `alphaToCoverage = true`.
2. **Вариация**: `col.rgb = adjust(col.rgb, aTint)`. Достаточно HSV-сдвига или простого `mix(luma, col, sat) * bright`.
3. **Свет**:
   - нормаль `n = texture(normalMap, uv).xyz*2-1` переводится в мир через TBN квада (тангенсы есть в glb, `TANGENT`);
   - для обратной стороны (`!gl_FrontFacing`) взять `n.xz *= -1`;
   - диффуз — wrap-Lambert `max(0,(dot(n,L)+0.4)/1.4)` плюс полусферный ambient;
   - просвет листвы: `+ k * pow(max(0, dot(V, -L)), 4)`, по аналогии с `foliage.ts`.
4. **Туман**: тот же, что у ландшафта и крон (`#include <fog_fragment>` или функция из `forestFog.ts`). Иначе карточки будут светиться на фоне тумана.
5. **Кросс-фейд LOD1 ↔ карточки** без сортировки: dither, он же screen-door.
   - `t = smoothstep(d0, d1, dist)`, где `dist` — расстояние экземпляра до камеры;
   - `noise = IGN(gl_FragCoord.xy)`;
   - в LOD1: `if (noise < t) discard;`, в карточке: `if (noise >= t) discard;`;
   - в зоне перехода рисуются оба объекта, это ≈ 1–2 % деревьев;
   - то же самое на границе карточки ↔ полоса: карточки растворяются в тумане до полосы.
6. Тени от карточек не отбрасывать (`castShadow=false`). Принимать — по желанию, на `high`.

## 5. Осторожно с overdraw на Iris Xe

- Цена карточек — это заполнение пикселей, а не треугольники: 3000 cross-карточек ≈ 12k tris. Плохо, когда большая карточка близко к камере. Поэтому карточек ближе ~25–40 м не должно быть.
- Подлесок — самый дорогой по overdraw: широкий, низкий и в кадре внизу.
  - Ставить его только по кромке леса, не ближе 2–3 м к обочине.
  - В первых 15 м от камеры разрежать ×2–3.
  - Никаких сплошных лент вдоль дороги.
- `discard` и `alphaToCoverage` мешают early-Z. Поэтому шейдер карточки должен быть дешёвым: 2 выборки текстур, без циклов, ray-march тумана по возможности считать в вершинном шейдере.
- MSAA 4x на Iris Xe стоит ощутимо. На `low`/`med` — только `alphaTest`.
- Чтобы увидеть overdraw, временно заменить фрагмент на `gl_FragColor = vec4(0.05)` с аддитивным блендингом.

## 7. Как измерять

- Одна и та же точка маршрута и камера (`&d=…&eye=…`), одно разрешение окна (1920×1080, `devicePixelRatio=1`), один пресет `&q=`.
- Прогрев 5 с, затем средний fps и 1 %-low за 10 с. Сравнивать «до/после», включая и выключая карточки флагом (например, `&cards=0`).
- В лог писать `renderer.info.render.calls`, `.triangles`, `renderer.info.memory.textures`.
- GPU-время — через `EXT_disjoint_timer_query_webgl2`, если доступно.
- Для замера запаса Chrome можно запускать с `--disable-gpu-vsync --disable-frame-rate-limit`.
- Отдельно замерить проезд по кромке леса: там подлесок и переход LOD1→карточки.
