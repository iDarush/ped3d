### 1.3 Обобщить `tools/prepare-local-models.mjs`

Сейчас скрипт знает только берёзу. Нужен список пород и одинаковое копирование для каждой:

```js
const SPECIES = [
  { id: "birch",   role: "tree",  models: ["birch"],              lods: [0, 1], strict: true },
  { id: "gentree", role: "tree",  models: ["gentree"],            lods: [0, 1] },
  { id: "alder",   role: "tree",  models: ["alder_a", "alder_b"], lods: [0, 1] },
  { id: "maple",   role: "tree",  models: ["maple_a", "maple_b"], lods: [0, 1] },
  { id: "abelia",  role: "shrub", models: ["abelia_a", "abelia_b"], lods: [0, 1] },
  { id: "cistus",  role: "shrub", models: ["cistus_a", "cistus_b"], lods: [0, 1] },
  { id: "lolium",  role: "grass", models: ["lolium_a", "lolium_b"], lods: [0] },
  { id: "setaria", role: "grass", models: ["setaria_a", "setaria_b"], lods: [0] },
];
// для каждой породы:
//   models/<id>/ktx2/<model>_lod<N>.glb      -> public/scene-assets/<id>/<model>_lod<N>.glb
//   models/<id>/ktx2/textures/*.ktx2         -> public/scene-assets/<id>/textures/
//   models/<id>/cards/<id>_card_cross.glb, <id>_cards.json, textures/*.ktx2
//                                            -> public/scene-assets/<id>/cards/...
// Список текстур брать из каталога (readdirSync), а не хардкодом: у maple и cistus нет bark_rough.
// birch: strict (как сейчас, бросает ошибку при неполном наборе); остальные: предупреждение и пропуск породы.
// Писать public/scene-assets/forest-manifest.json: какие породы реально скопированы, их роли и файлы.
```

Важно:
- **Каждой породе своя папка** в `public/scene-assets/<id>/`. Имена текстур совпадают (`bark_color.ktx2` у всех), а glb ссылаются на них относительным путём `textures/...`.
- Выходные пути берёзы остаются прежними, `birchPreview.ts`/`birchLod.ts` менять для этого не нужно.
- Перед копированием очищать `public/scene-assets/<id>/` (только папки пород), чтобы не оставались старые файлы.
- Рантайм должен читать `forest-manifest.json` и спокойно работать с любым подмножеством пород.

## Часть 2. Как строить лес и подлесок на новых моделях

### 2.1 Ассеты

Высоты реальные, в метрах. Ось Y вверх, начало координат в основании ствола. Материалов два: `bark` (непрозрачный) и `foliage` (alphaTest 0.5, double-sided). У трав только `foliage`.

| порода | роль | модели (высота) | LOD0 / LOD1 треуг. | атлас карточек | ячейка, px | h0 в json |
|---|---|---|---|---|---|---|
| birch | дерево | birch 4.94 м | 3 652 / 1 349 | 2048×2048 | 256×448 | 4.943 |
| gentree | дерево (осень) | gentree 16.8 м | 4 026 / 1 234 | 2048×2048 | 256×448 | 16.813 |
| alder | дерево | a 14.76 м, b 10.72 м | ~4 220 / ~1 250 | 2048×1536 | 256×384 | 14.76 |
| maple | дерево (осень) | a 12.46 м, b 12.22 м | ~4 200 / ~1 250 | 2048×1264 | 256×316 | 12.46 |
| abelia | куст | a 1.44 м, b 1.19 м | ~1 385 / 520 | 1024×464 | 128×116 | 1.437 |
| cistus | куст | a 1.03 м, b 1.26 м | ~1 400 / 520 | 1024×400 | 128×100 | 1.032 |
| lolium | трава | a 0.47 м, b 0.27 м | 6 | — | — | — |
| setaria | трава | a 0.28 м, b 0.17 м | 6 | — | — | — |

Новые ассеты: ~15 МБ загрузки, ~29 МБ GPU (оценка, подробно в `_preview/budget.json`).

### 2.2 Карточки: что читать из json, а не хардкодить

Формат json у всех пород тот же, что у берёзы (у новых есть лишние поля, у берёзы — дополнительно `understory`/`forest_band`). Отличаются размеры, поэтому:
- Сдвиг строки: `v += row * cell_px[1] / atlas.size[1]`, столбца: `u += col * cell_px[0] / atlas.size[0]`. Если сейчас в шейдере зашито `448/2048`, вынести это в uniform для каждой породы.
- Столбец = азимут обзора с шагом 45° (`tree_cells.columns`: в glTF направление на камеру x=sin a, z=cos a, против часовой стрелки сверху). Брать `col = round((azimuth_to_camera − instance_yaw) / 45°) mod 8`. Пока азимутные столбцы не подключены, на столбце 0 тоже работает, но дерево «поворачивается» за камерой.
- Масштаб: единица меша карточки = высота варианта 0 (`h0`). **Масштаб экземпляра s (м) одинаковый для карточки и модели.** Модель надо нормализовать на тот же `h0`, а не на собственный bbox каждого варианта, иначе вариант b не совпадёт со своей карточкой.

Строки (варианты) и соответствие модели, чтобы при смене LOD ничего не прыгало:

| порода | row 0 | row 1 | row 2 | row 3 |
|---|---|---|---|---|
| alder, maple, abelia, cistus | модель a | модель b | a зеркальная | b зеркальная |
| birch, gentree | модель | модель зеркальная | изменённая (тоньше), модели нет | изменённая (шире), модели нет |

- Зеркальные строки отражены по X glTF. Если у экземпляра зеркальная строка, его модель тоже нужно рисовать с scale.x = −1. В InstancedMesh отрицательный масштаб на экземпляр переворачивает обход граней, поэтому зеркальные экземпляры — **отдельный InstancedMesh**, у материала коры `side = BackSide` (листва и так double-sided).
- Для birch и gentree строки 2 и 3 брать только для экземпляров дальше радиуса моделей, к которым не подъедешь ближе 40 м (например, глубже 30 м от дороги). Иначе при переходе на модель силуэт заметно поменяется.
- В карточках берёзы есть небольшой оттенок по строкам (`variants[].tint`). Для берёзы row 1 его стоит повторить в цвете экземпляра модели или игнорировать: разница ±6%.

### 2.3 Определённость: чтобы ничего не прыгало между кадрами

Главное требование Дарьи.
- Порода, вариант (row), поворот, масштаб и позиция экземпляра — **чистая функция от мировых координат** (хэш ячейки сетки и seed). Никакого `Math.random()` при refill: повторная генерация той же ячейки должна давать тот же набор.
- Выбор представления (модель, LOD1, карточка) с гистерезисом: экземпляр, уже ставший моделью, остаётся ею, пока не уйдёт дальше порога + 2 м или пока ближе не появится другой кандидат с запасом больше 2 м. Это уменьшит перестановки при исчерпании бюджета 3+8.
- Переходы — тем же экранным dither, что сейчас у берёзы (противоположные маски у двух представлений).

### 2.4 Состав и расстановка

Начальные пропорции для лиственного или смешанного леса из OSM (подбираются на глаз):
- **Деревья:** birch 35%, alder 25%, gentree 20%, maple 20%. Высота варианта a (row 0) у экземпляра 8–12 м, предел 12 м как сейчас; s = эта высота в метрах (меши нормализованы на h0). Для gentree это примерно 0,6–0,7 от исходной, для берёзы до ×2,4, как сейчас. Вариант b получается в своей пропорции к a автоматически.
- **Сезон:** maple и gentree осенние (жёлто-красные). Сейчас лес выходит ранней осенью. Если нужно лето, перекрасить листву скажет Грок (поменяется только текстура foliage_color).
- **Расстояние между деревьями:** Poisson-disk, минимум 4–6 м; у кромки леса реже.
- **Кусты** (abelia 60%, cistus 40%): полоса 0–8 м от кромки леса группами по 3–7, шаг внутри группы 1–2 м; под пологом редко, около 0,03 на м². Масштаб 0,8–1,3. Cistus средиземноморский, поэтому его меньше.
- **Трава** (lolium 70%, setaria 30%): обочина 1–4 м от края асфальта, кромка леса, поляны. Плотность 0,5–1,5 пучка на м² у дороги. Масштаб 0,8–1,4, поворот любой. На асфальт не заходить.

### 2.5 Дистанции и бюджеты (предложение для med)

| роль | модель LOD0 | LOD1 | карточка | дальше |
|---|---|---|---|---|
| дерево | < 20 м | 20–40 м | 40–300 м (dither 38–42) | прежний дальний LOD или полоса в тумане |
| куст | < 12 м | 12–30 м | 30–120 м | ничего (туман) |
| трава | < 35 м, одно представление | — | — | плотность плавно убывает 25 → 35 м: экземпляр рисуется, если `hash < 1 − (d−25)/10` |

- Бюджет моделей деревьев общий на все породы (3+8 на med), а не на каждую.
- У кустов свой бюджет, примерно 6+20; тени у кустов и травы выключить.
- Вызовов отрисовки на породу примерно 2 (LOD0) + 2 (LOD1) + 1 (карточки), плюс 1 на зеркальную группу. Все 8 пород дадут +30–40 calls. Поэтому вводить по этапам и замерять каждый.

### 2.6 Порядок внедрения (каждый шаг — замер в 3910 и 4620 м, как раньше)

1. Скрипт подготовки и манифест (часть 1), без изменения картинки.
2. Карточки всех 4 деревьев вместо одной берёзы (`?forest=mix&cards=1`), строки 0/1, столбец по азимуту.
3. Модели деревьев a/b с общим бюджетом 3+8 и гистерезисом.
4. Кусты у кромки (модели и карточки).
5. Трава на обочинах.
6. Зеркальные строки и поворот азимутных столбцов, если 2–5 укладываются в бюджет.

Флаг для сравнения: `?view=proc&forest=mix&d=4620&q=med` против `birch=1` и `birch=all`.

### 2.7 Известные мелочи
- У alder b корни уходят на 0,28 м ниже нуля, LOD1 у maple — на 0,11 м. Это нормально, они уходят в землю.
- Lolium в исходнике был 3–6 см, Грок увеличил его ×10 (сейчас 0,27–0,47 м).
- Текстура setaria 1024² — для крошечного пучка много; Грок может уменьшить до 512² (−2 МБ GPU).
- Тонкие стебли setaria вблизи могут выглядеть оторванными. Карты просвечивания (translucency) не используются.
- Цвет карточек — ETC1S. Если тонкие ветки замерцают в движении, Грок даст атлас в UASTC.
- Лицензия Maxtree: Дарья подтверждает сама. Это личный локальный проект, ассеты не публиковать.
