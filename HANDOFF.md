## Договорённости и текущие интерфейсы

- Цель: художественно убедительная процедурная сцена маршрута для ped, с учётом слабой видеокарты ноутбука. Приоритет — ближнее окружение, осмысленное размещение и качество ассетов. Стабильные 30 FPS — целевой ориентир, пока не подтверждённый замерами поездки.
- `RideScene3D.vue`: `scene` — адрес подготовленной сцены; `points` — геотрек; `distanceM` — метры вдоль **всего геотрека**, а не от начала процедурного сегмента; `speedKph` — км/ч для сглаживания между обновлениями.
- Источник позиции — серверная дистанция, преобразованная в дистанцию геотрека при интеграции. Для режима section учитывать преобразование через долю маршрута, описанное в `INTEGRATION.md`; не подставлять тренировочные метры напрямую без учёта этого соответствия.
- `RideClock` сглаживает позицию, ограничивает экстраполяцию двумя секундами и делает скачок при расхождении более 60 м. Скорость не заменяет серверную позицию. На паузе передавать скорость 0.
- `points`: `[lon, lat, ele?]`, долгота первой. `cameraMode`: `eye | chase`; по умолчанию высота глаз 1,6 м, упреждение 30 м, FOV 60°.
- Готовая сцена `muritz-3k` покрывает примерно 2900–5900 м исходного маршрута. Загрузка: `?view=proc`; диагностические точки: `d=3000`, `3700`, `4530`.
- Качество задаётся `src/lib/quality.ts`, параметр URL `q=low|med|high`, по умолчанию `med`. Проп `shadows=false` отключает тени независимо от пресета. `wind=false` отключает ветер.
- Локальная берёза: `&birch=1` только при `npm run dev`, по умолчанию выключена; новый необязательный проп `birchPreview` передаётся в `RideScene3D`. Production игнорирует флаг. Для сравнения убрать параметр или задать `birch=0`.

## Проверки и ограничения

- Сборка: `npm run build`; тесты: `npx vitest run` (сейчас 8 тестов: 6 геотрека и 2 ограничений сглаживания дороги).
- Просмотр: `npm run dev`, затем `http://localhost:5180/?view=proc`.
- Снимки: `node shoot-proc.mjs`; по умолчанию нужен сервер на порту 4173, для dev задать `BASE=http://localhost:5180/`. Переменные `DS`, `CAMS`, `EXTRA` ограничивают точки, камеры и параметры URL.
- Скрипт находит Chrome/Edge на Windows, Chrome/Chromium на Linux; можно задать `CHROME_PATH`. Результаты — `shots/`, переопределение `SHOTS_DIR`; `SOFTWARE_GL=1` принудительно включает SwiftShader.
- Headless-проверка трёх статичных кадров с GPU readback не заменяет замер FPS и плавности в движении. Системный запрос GPU был недоступен; через WebGL Chrome определена Intel Iris Xe, ANGLE / Direct3D11.
- После прохода дороги low: 3700 м — 99 calls / 430 069 triangles; 4530 м — 59 / 64 736. Геометрический бюджет не вырос, стоимость шейдера на пиксель выросла.
- Финальные med-снимки: деревня 3000 м, поле 3700 м, лес 4530 м. Ошибок рендеринга нет; в деревне было предупреждение ANGLE о точности вычислений. Прогретые статичные кадры примерно 19 / 89 / 40 мс соответственно; поле остаётся тяжёлым.
- Ближняя хвоя переработана короткими наклонёнными пучками, но деревья по-прежнему используют карточки; дальний LOD остался прежним. Дорога улучшена частично; полноценные переходы грунта и переработка распределения растительности ещё не сделаны.

Геометрия каждого LOD приводится к единичной высоте, чтобы использовать текущие матрицы экземпляров; материалы LOD0 переиспользуются LOD1. Loader/геометрии/материалы/текстуры освобождаются при завершении.
- В dev по `birch=1` ближайшие обычные лиственные деревья заменяются берёзами: до 8 LOD0 в радиусе 20 м, до 16 LOD1 до 35 м (и не дальше detailR). Выбор по расстоянию, размеры instance-буферов ограничены этими бюджетами. Остальные деревья процедурные. Это художественная замена части generic broadleaf, не восстановление фактического расположения берёз из OSM.
- Исходная модель молодая, высотой около 4,94 м. После нормализации высота экземпляра ограничена 12 м, чтобы не растягивать стройный ствол до старых 20+ м. Сохраняются затенение под кронами, лесной туман, ветер и соответствующие маски теней. Возможны заметные переключения между моделью и старой кроной на границах бюджета/радиуса — экспериментальный LOD, плавный переход ещё не реализован.
- В `window.__rideInfo.birches` и вывод скрипта снимков добавлены фактические количества LOD0/LOD1. Отсутствующие или некорректные локальные файлы дают предупреждение и возврат к процедурным деревьям.
