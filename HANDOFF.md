## Договорённости и текущие интерфейсы

- Цель: художественно убедительная процедурная сцена маршрута для ped, с учётом слабой видеокарты ноутбука. Приоритет — ближнее окружение, осмысленное размещение и качество ассетов. Стабильные 30 FPS — целевой ориентир, пока не подтверждённый замерами поездки.
- `RideScene3D.vue`: `scene` — адрес подготовленной сцены; `points` — геотрек; `distanceM` — метры вдоль **всего геотрека**, а не от начала процедурного сегмента; `speedKph` — км/ч для сглаживания между обновлениями.
- Источник позиции — серверная дистанция, преобразованная в дистанцию геотрека при интеграции. Для режима section учитывать преобразование через долю маршрута, описанное в `INTEGRATION.md`; не подставлять тренировочные метры напрямую без учёта этого соответствия.
- `RideClock` сглаживает позицию, ограничивает экстраполяцию двумя секундами и делает скачок при расхождении более 60 м. Скорость не заменяет серверную позицию. На паузе передавать скорость 0.
- `points`: `[lon, lat, ele?]`, долгота первой. `cameraMode`: `eye | chase`; по умолчанию высота глаз 1,6 м, упреждение 30 м, FOV 60°.
- Готовая сцена `muritz-3k` покрывает примерно 2900–5900 м исходного маршрута. Загрузка: `?view=proc`; диагностические точки: `d=3000`, `3700`, `4530`.
- Качество задаётся `src/lib/quality.ts`, параметр URL `q=low|med|high`, по умолчанию `med`. Проп `shadows=false` отключает тени независимо от пресета. `wind=false` отключает ветер.
- Новый лес: `?view=proc&forest=mix&d=4620&q=med`. Необязательные props `forestMix` и `forestStage`; при forest=mix прежние birch-флаги игнорируются. По умолчанию forestStage=full: деревья, модели, кусты, трава, зеркальные формы и плавные ракурсы. Для воспроизведения этапов: forestStage=cards|trees|shrubs|grass|full. Значение cards=0 относится только к старому берёзовому режиму, не отключает обязательный fallback нового леса.
- Контакт деревьев: prop `treeGrounding`, URL `grounding=off|shade|full`, по умолчаниюfull. off — прежний грунт/стволы, shade — затемнение под корнем и градиент коры/карточки, full — дополнительно3–6 пучков в0,3–1,2м от дерева. Работает для forest=mix. Координаты корней/высоты упакованы вBA существующей canopy texture (RGBA8 вместоRG8), исходныеRG сохранены, новых calls/texture objects для затемнения нет; одно дополнительное чтение в террейне до60м.
- При grounding=full пучки у стволов работают даже с forestStage=trees/cards; эти диагностические этапы по-прежнему не включают траву обочин. В полном forestStage=full пучки добавляются в уже имеющиеся4 травяных InstancedMesh без новых групп. Если импортированная трава прежде была выключена (tufts0), включение колец впервые создаёт4 grass calls/4 GPU textures (две породы×два варианта; это не call на дерево). `vegetation.rootTufts` и панель roots показывают отправленные корневые пучки отдельно от общего grass/tufts, включая запас shader fade.
- Runtime читает scene-assets/forest-manifest.json. Неполные optional-породы пропускаются, отсутствующие доли перенормируются. Пустой набор не обращается к GPU-моделям и сохраняет сцену без импортированных деревьев; прежний процедурный покров травы остаётся. Источники в models/raw не копируются, tools/asset-pipeline не запускается.
- В смеси деревья имеют детерминированные породу/вариант/yaw/масштаб по координатам, 8–12 м для варианта a, минимум 5 м между исходными позициями. Кусты получают отдельную расстановку у кромки; ковер прежней травы заменяется текстурными пучками только в заданных областях. Общая селекция деревьев сохраняет бюджеты birchDetailCount/birchSimpleCount, +6 м удержания и fade 0,4 с. LOD у занятого экземпляра не повышается просто при пересечении 20 м.
- В смеси дальние cross продолжаются до прежнего cardR (900/1600/2600), а не обрываются на 180/300/400 м: лес через поле сохранён без отдельного кольца/полосы. Столбец атласа следует относительному азимуту; в full соседние ракурсы смешиваются в узкой угловой зоне, где добавляется вторая выборка карты. Размеры всех UV-ячеек берутся из JSON. Модели нормализованы на общий h0 породы; отражённые модели имеют отдельную геометрию с исправленным winding и положительные матрицы экземпляров.
- `window.__rideInfo.vegetation` содержит фактические lod0/lod1 деревьев, shrubLod0/shrubLod1, количество отправленных карточек/кустов/пучков и список загруженных пород; trees — число детерминированных исходных деревьев всего сегмента. Часть отправленной геометрии скрывается shader fade. Панель показывает основные числа.
- Локальная берёза: `&birch=1` работает и при `npm run dev` (5180), и в `npm run build` + `npm run preview` (4173), по умолчанию выключена. Необязательный проп `birchPreview` передаётся в `RideScene3D`. Для сравнения убрать параметр или задать `birch=0`. Панель показывает фактические количества `birch LOD0+LOD1`.
- При birch=1 cross-карточки включены по умолчанию; `cards=0` выключает только их, `cards=1` включает. Новый необязательный проп `birchCards`. Панель показывает число отправленных карточек, включая запас для переходов. Радиусы карточек и ширина перехода — в QualityPreset.
- Эксперимент `birch=all`: необязательный проп `allBirches`, принудительно включает модели и cross-карточки. Все исходные экземпляры (включая кустовые формы) становятся берёзами; позиции, yaw и исходные пропорции сохранены, высота ограничена 12 м. Бюджет моделей прежний, остальные экземпляры — cross на всей дальности cardR. В этом режиме модель и её LOD закрепляются до выхода из радиуса удержания (радиус входа + 6 м; med 42/48 м), переход модель/карточка — временной complementary dither 0,4 с. Освобождающаяся модель занимает слот до конца перехода, бюджет не увеличивается. Процедурного fallback нет; если карточки недоступны, загрузка завершается ошибкой. Обычный birch=1 не меняется.

## Проверки и ограничения

- Сборка: `npm run build`; тесты: `npx vitest run` (29 тестов: геотрек, дорога, пиксельный бюджет, LOD/селектор, подготовка ассетов, мировая идентичность/обочина, отражение геометрии, пустой runtime-манифест, лесная маска/подложка, упаковка контакта и пучки у корней).
- Просмотр: `npm run dev`, затем `http://localhost:5180/?view=proc`.
- Снимки: `node shoot-proc.mjs`; по умолчанию нужен сервер на порту 4173, для dev задать `BASE=http://localhost:5180/`. Переменные `DS`, `CAMS`, `EXTRA` ограничивают точки, камеры и параметры URL.
- Скрипт находит Chrome/Edge на Windows, Chrome/Chromium на Linux; можно задать `CHROME_PATH`. Результаты — `shots/`, переопределение `SHOTS_DIR`; `SOFTWARE_GL=1` принудительно включает SwiftShader.
- Headless-проверка трёх статичных кадров с GPU readback не заменяет замер FPS и плавности в движении. Системный запрос GPU был недоступен; через WebGL Chrome определена Intel Iris Xe, ANGLE / Direct3D11.
- После прохода дороги low: 3700 м — 99 calls / 430 069 triangles; 4530 м — 59 / 64 736. Геометрический бюджет не вырос, стоимость шейдера на пиксель выросла.
- Финальные med-снимки: деревня 3000 м, поле 3700 м, лес 4530 м. Ошибок рендеринга нет; в деревне было предупреждение ANGLE о точности вычислений. Прогретые статичные кадры примерно 19 / 89 / 40 мс соответственно; поле остаётся тяжёлым.
- Ближняя хвоя переработана короткими наклонёнными пучками, но деревья по-прежнему используют карточки; дальний LOD остался прежним. Дорога улучшена частично; полноценные переходы грунта и переработка распределения растительности ещё не сделаны.

Следующий шаг — живой просмотр пользователем, затем точечная художественная настройка плотности/контакта с грунтом и профиль оставшихся задержек, без увеличения бюджетов по умолчанию.
